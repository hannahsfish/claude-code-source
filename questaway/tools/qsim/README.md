# qsim：QuestAway 统一模拟器

用游戏自己的引擎（1.0.9，存档版本 22）离线模拟刷图、巨像、首领。一个浏览器、4 个页面并行，带结果缓存和误差估计。

```
node qsim.js job.json [--workers 4] [--out result.json] [--no-cache] [--quiet]
```

本目录只有模拟器代码。游戏引擎页面（`engine.html`）和同行玩家数据（`comp_*.json`）来自游戏本体和真实存档，不放进仓库。

## 任务文件

```json
{
  "save": "存档路径",
  "companions": "cal | real | synth | strong | none | 文件路径",
  "variants": [ { "name": "base", "ops": [] }, { "name": "...", "ops": [ ... ] } ],
  "measures": [
    { "type": "farm", "stage": [2, 10, 7], "seeds": 6 },
    { "type": "col", "samples": 3 },
    { "type": "boss", "act": [2, 10], "n": 10, "preset": "巨像" },
    { "type": "stats", "hero": "thief", "keys": ["attack", "haste"] }
  ]
}
```

第一个方案是基准，其余方案的涨幅都相对它算，按相同的随机种子配对，给出 ± 标准误。

`ops`（对存档的修改，只在模拟里生效）：

| op | 作用 |
|---|---|
| `preset` | 切换天赋预设：`{hero:"thief" 或 "*", name:"巨像"}` |
| `enhance` | 强化：`{hero, slot, level, awake}`，awake 是已唤醒的节点数 |
| `item` | 换一件装备：`{hero, slot, base, rarity, level, enchant?, sockets?, enhance?, awake?}`。词条、数值、孔数、附魔数值全部由引擎公式生成 |
| `gems` / `enchant` | 改宝石、改附魔 |
| `level` | 改等级 |
| `buff` | 换药水：`{id:"might"}` |
| `bestiary` | 改图鉴击杀数 |
| `talisman` / `untalisman` | 镶、拆法阵护符 |
| `build` | 改天赋点或技能 |
| `hero` | 用一份完整的英雄数据顶替场上某人 |
| `set` | 通用路径赋值 |

## 口径和校准

**刷图**：每个种子模拟 10 分钟，过图间隔按 4 秒算，药水计入（洞察药水是和经验加成相加，实际约 +8%，不是 +25%）。
对照两段真实存档区间：模拟比实际低 4%～19%，差的部分主要是巨像宝箱给的经验。

**巨像**：每种类型打一场，10 种合计。默认强度 2200、时长 1800 秒、同行 5 队、自动切到名为「巨像」的预设。
用 3 场存档里记录的真实战斗（104、107、108 号存档）校准：

| 同行玩家设定 | 模拟 / 实际 |
|---|---|
| 5 队弱玩家（`real`，取自一场真实战斗） | 0.62～0.82，平均 0.71 |
| 4 队弱玩家 + 1 个中等装备的女巫（`cal`，默认） | 1.05～1.24，平均 1.13 |
| 5 队满级女巫队（`strong`） | 4～7 倍 |

倒地次数三场都和实际一致（13/12、23/26、21/22）。

- 伤害只统计自己队伍的输出，但同行玩家的减益会放大它，所以绝对值强烈依赖同场的人是谁，误差按 ±15% 看。
- 装备、强化这类改动的相对涨幅在 `cal` 和 `real` 两种设定下基本一致，可信。
- 「自己带女巫」的收益依赖同场有没有别的女巫，要两种设定都看。

**误差**：单场巨像的随机波动约 ±8%，10 种合计后约 ±2.5%，默认 3 个样本后约 ±1%。

## 速度

同样的 57 个方案（每个 4 个刷图种子 + 10 场巨像）：旧脚本 178 秒，qsim 71 秒；重复运行走缓存，0.3 秒。

## 和旧脚本相比修掉的问题

- 巨像预设不再用过期的手抄文件，直接读存档里的「巨像」预设。
- 巨像强度、时长、同行玩家改成按真实记录校准的默认值。
- 生成装备不再手算修正系数，词条、孔数（永恒多 1 孔）、附魔数值（随品质变化）都调引擎函数。
- 刷图计入药水。
- 每个结果带误差，不再凭单次结果下结论。
- 引擎函数尽量走具名导出，只剩 `est2` 一个内部函数依赖当前版本的注入。
