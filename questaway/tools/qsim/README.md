# qsim：QuestAway 统一模拟器

用游戏自己的引擎（1.0.9，存档版本 22）离线模拟刷图、巨像、首领。一个浏览器、4 个页面并行，带结果缓存和误差估计。

```
node qsim.js job.json [--workers 4] [--out result.json] [--no-cache] [--quiet]
```

本目录只有模拟器代码。游戏引擎页面（`engine.html`）和同行玩家数据（`comp_*.json`）来自游戏本体和真实存档，不放进仓库。

## 任务文件

```json
{
  "save": "存档路径",
  "companions": "cal | real | synth | strong | none | 文件路径",
  "variants": [ { "name": "base", "ops": [] }, { "name": "...", "ops": [ ... ] } ],
  "measures": [
    { "type": "farm", "stage": [2, 10, 7], "seeds": 6 },
    { "type": "col", "samples": 3 },
    { "type": "boss", "act": [2, 10], "n": 10, "preset": "巨像" },
    { "type": "stats", "hero": "thief", "keys": ["attack", "haste"] }
  ]
}
```

第一个方案是基准，其余方案的涨幅都相对它算，只拿随机种子（样本号）相同的结果配对，给出 ± 标准误。

有任务出错时：开头和结尾各报一次，同时写到标准错误；出错方案那一行标「⚠ 缺 N 个任务」；进程退出码是 1。

预设：`farm` 默认套名为「推图」的预设，`col` 默认套「巨像」，`boss`、`stats` 默认用存档当前配法。
每个测量都可以写 `"preset": "名字"` 换预设，或写 `"preset": null` 用存档当前配法。
预设在 `ops` 之后套用，所以用 `build` 改了配法的英雄如果有同名预设，要写 `"preset": null`。
某个英雄没有这个名字的预设时沿用存档当前配法，输出里会列出是谁。

`ops`（对存档的修改，只在模拟里生效）：

| op | 作用 |
|---|---|
| `preset` | 切换天赋预设：`{hero:"thief" 或 "*", name:"巨像"}` |
| `enhance` | 强化：`{hero, slot, level, awake}`，awake 是已唤醒的节点数 |
| `item` | 换一件装备：`{hero, slot, base, rarity, level, enchant?, sockets?, enhance?, awake?}`。词条、数值、孔数、附魔数值全部由引擎公式生成；不写 `enchant` 时沿用原来的附魔属性和卷轴阶数 |
| `gems` / `enchant` | 改宝石、改附魔 |
| `level` | 改等级 |
| `buff` | 换药水：`{id:"might"}` |
| `bestiary` | 改图鉴击杀数 |
| `talisman` / `untalisman` | 镶、拆法阵护符 |
| `build` | 改天赋点或技能 |
| `hero` | 用一份完整的英雄数据顶替场上某人（id 和别人重复时自动另起一个） |
| `remove` | 让某个英雄下场：`{hero:"engineer"}`，用来看少了他队伍掉多少 |
| `order` | 调整站位：`{classes:["priest","thief",...]}`。1 号位挨打最多 |
| `set` | 通用路径赋值 |

## 口径和校准

**刷图**：每个种子模拟 10 分钟，过图间隔按 4 秒算，药水计入（洞察药水是和经验加成相加，实际约 +8%，不是 +25%）。
默认套「推图」预设：存档如果是在巨像进行中存的，场上是「巨像」预设，不切换的话经验会低约 2%、金币低 3%～4%。
这 10 分钟里升级的英雄，跨过的等级所需经验会加回来。队伍打不动这一关时经验记 0 并标成倒地。
有人倒地时引擎会像游戏里一样往回退关：这时数字是退到的那一关的，输出里会写明退到了哪一关。
对照两段真实存档区间：模拟比实际低 4%～19%，差的部分主要是巨像宝箱给的经验。

**巨像**：每种类型打一场，10 种合计。默认强度 2200、时长 1800 秒、同行 5 队、自动切到名为「巨像」的预设。
用 4 场存档里记录的真实战斗（104、107、108、112 号存档）校准：

| 同行玩家设定 | 模拟 / 实际 |
|---|---|
| 5 队弱玩家（`real`，取自一场真实战斗） | 0.62～0.97，平均 0.77 |
| 4 队弱玩家 + 1 队带 79 级女巫的真实队伍（`cal`，默认） | 0.73～1.09，平均 0.90 |
| 4 队弱玩家 + 1 个 94 级传说 60 女巫（`cal_wz60`） | 1.05～1.47，平均 1.2 |
| 5 队满级女巫队（`strong`） | 4～7 倍 |

倒地次数四场都和实际一致（13/12、25/26、22/22、14/14）。

- 伤害只统计自己队伍的输出，但同行玩家的减益会放大它，所以绝对值强烈依赖同场的人是谁。
- **绝对值只能当下限看。** 上表之后又对照了两场（都用 `cal`）：115 号存档 95 亿对实际 135.6 亿（0.70），118 号存档 145～153 亿对实际 234.2 亿（0.62～0.65）；
  118 那场换成它自己开打时的 5 队真实同行，是 131 亿（0.56），从开打 18.6 秒的真实状态接着模拟也只到 142 亿。
  版本没有变（存档里的符文引擎都认识），倒地次数仍然一致（4/4、5/5）。最可能的原因是真实战斗中同行队伍会中途换人，模拟里从头到尾是同一批。
  119 号存档那场（同样的装备，强度 2521，413 秒）实际只有 123.3 亿，模拟 111～120 亿（0.90～0.97）：装备没变，实际每秒伤害却比 118 那场低 28%，说明差的就是同行队伍。
  120 号存档那场是打满的（强度 1709，2871 秒）：实际 1272.7 亿，模拟 1048～1061 亿（0.82～0.83），倒地 21/21。
  122 号存档那场（强度 4537，6025 秒，第 2 种巨像，刺客站 1 号位）：实际 2066.3 亿，模拟 1745 亿（0.84），倒地 43 / 42。
- 刷图对照：121 → 122 之间挂了 16.4 小时的 10-9，实际每人每小时 1.092 亿经验、537 万金币；模拟 1.048 亿、542 万，经验低 4%。
- 刷图对照：118 → 119 之间挂了 10.5 小时的 10-9，实际每人每小时 1.07 亿经验、592 万金币；模拟 1.023 亿、539 万，低 4% 和 9%。
- 相对涨幅仍然对得上：115 → 118 两场之间（刺客武器 +3 唤醒、全队升 97 级），实际每秒伤害 +51%，模拟预测 +47%。
- 装备、强化这类改动的相对涨幅在 `cal` 和 `real` 两种设定下基本一致，可信。
- 「自己带女巫」的收益依赖同场有没有别的女巫，要两种设定都看。

**误差**：单场巨像的随机波动约 ±8%，10 种合计后约 ±2.5%，默认 3 个样本后约 ±1%。

## 速度

同样的 57 个方案（每个 4 个刷图种子 + 10 场巨像）：旧脚本 178 秒，qsim 71 秒；重复运行走缓存，0.3 秒。

## 和旧脚本相比修掉的问题

- 巨像预设不再用过期的手抄文件，直接读存档里的「巨像」预设。
- 巨像强度、时长、同行玩家改成按真实记录校准的默认值。
- 生成装备不再手算修正系数，词条、孔数（永恒多 1 孔）、附魔数值（随品质变化）都调引擎函数。
- 刷图计入药水。
- 每个结果带误差，不再凭单次结果下结论。
- 引擎函数尽量走具名导出，只剩 `est2` 一个内部函数依赖当前版本的注入。
