# qsim：QuestAway 统一模拟器

用游戏自己的引擎离线模拟刷图、巨像、首领、爬塔。当前对应客户端 1.1.3（引擎数据版本 24），1.1.0 也能用。一个浏览器、4 个页面并行，带结果缓存和误差估计。

```
node qsim.js job.json [--workers 4] [--out result.json] [--no-cache] [--quiet]
```

本目录只有模拟器代码。游戏引擎页面（`engine.html`）和同行玩家数据（`comp_*.json`）来自游戏本体和真实存档，不放进仓库。

### 换新客户端

1. 从客户端 exe 里解出内嵌的 `index.html`（资源表是 brotli 压缩的文件列表）。
2. `python3 -I build_engine.py <解出的 index.html> engine.html`：按代码结构找到引擎的具名导出表（挂到 `window.__NS`）和估算每秒击杀的内部函数（挂到 `window.__QA.est2`，刷图要用），不改游戏逻辑。混淆后的变量名每版都不同，脚本不写死名字。
3. 换了 `engine.html` 后缓存会自动失效（缓存键里有引擎文件的大小和修改时间）。

## 任务文件

```json
{
  "save": "存档路径",
  "companions": "cal | real | synth | strong | cal_wz60 | none | 文件路径（脚本目录下有 comp_<名字>.json 的名字都能直接写）",
  "variants": [ { "name": "base", "ops": [] }, { "name": "...", "ops": [ ... ] } ],
  "measures": [
    { "type": "farm", "stage": [2, 10, 7], "seeds": 6 },
    { "type": "col", "samples": 3 },
    { "type": "boss", "act": [2, 10], "n": 10, "preset": "巨像" },
    { "type": "stats", "hero": "thief", "keys": ["attack", "haste"] },
    { "type": "tower", "seeds": 4, "ms": 3600000, "andares": [95], "unlock": true }
  ]
}
```

第一个方案是基准，其余方案的涨幅都相对它算，只拿随机种子（样本号）相同的结果配对，给出 ± 标准误。

有任务出错时：开头和结尾各报一次，同时写到标准错误；出错方案那一行标「⚠ 缺 N 个任务」；进程退出码是 1。

预设：`farm` 默认套名为「推图」的预设，`col` 默认套「巨像」，`boss`、`stats` 默认用存档当前配法。
每个测量都可以写 `"preset": "名字"` 换预设，或写 `"preset": null` 用存档当前配法。
测量自带的默认预设（巨像用「巨像」、刷图用「推图」）只套给 `ops` 没有动过配法的英雄：被 `preset`、`build`、`hero` 操作指定过配法的英雄保持 `ops` 给的配法，不会被默认预设盖掉。
某个英雄没有这个名字的预设时沿用存档当前配法，输出里会列出是谁。

`ops`（对存档的修改，只在模拟里生效）：

| op | 作用 |
|---|---|
| `preset` | 切换天赋预设：`{hero:"thief" 或 "*", name:"巨像"}` |
| `enhance` | 强化：`{hero, slot, level, awake}`，awake 是已唤醒的节点数；不写就保留原来的唤醒数（不超过这一级的上限） |
| `item` | 换一件装备：`{hero, slot, base, rarity, level, enchant?, sockets?, enhance?, awake?}`。词条、数值、孔数、附魔数值全部由引擎公式生成；不写 `enchant` 时沿用原来的附魔属性和卷轴阶数 |
| `gems` / `enchant` | 改宝石、改附魔 |
| `level` | 改等级 |
| `buff` | 换药水：`{id:"might"}` |
| `bestiary` | 改图鉴击杀数 |
| `talisman` / `untalisman` | 镶、拆法阵护符 |
| `build` | 改天赋点或技能 |
| `hero` | 用一份完整的英雄数据顶替场上某人（id 和别人重复时自动另起一个） |
| `remove` | 让某个英雄下场：`{hero:"engineer"}`，用来看少了他队伍掉多少 |
| `order` | 调整站位：`{classes:["priest","thief",...]}`。1 号位挨打最多 |
| `set` | 通用路径赋值 |
| `pets` | 塔宠物收藏（`petState.fixados`）：`{set:[...]}` 换成这份列表，`{add:[...]}` / `{drop:[...]}` 在现有收藏上加减。收藏里的全部生效、效果叠加，没有栏位上限 |

## 口径和校准

**爬塔**（`tower`）：用游戏自己的自动爬塔（piloto，默认 `subir` 往上爬、倒下 `recuar` 退一层），只推进时间，每 10 秒看一次状态。
不写 `andares` 就从存档里塔的当前位置接着爬（沿用这一趟的挑战、诅咒、祝福）；写了就从那一层重新进塔，`unlock:true` 先把纪录解锁到该层。
每个方案输出：倒地合计、平均停在第几层、每次最远到哪、每人每小时升华经验（和基准同种子配对的涨幅）、金币、过的房间数、倒在哪几层。
换种子是把时钟往后挪；写了 `andares` 时还把「第几趟」加上种子号（塔的地图种子由它决定），房间布局跟着变；一般 4～8 次、每次 1～3 小时才看得出差别。

- 已确认生效：站位、装备、技能、天赋、药水、塔宠物（收藏的全部叠加，石巨人、灰烬凤凰、钟楼蝙蝠影响最大）。
- **升华和遗物**：两者都不直接加属性，只抬高每个房间「请求」（`pedido`）的上限（`NS.tetoDoDesafio`）：经验、金币、英雄加成（`herois.vezes/mais`）、更多怪、首领伤害。
  游戏进塔时默认把请求填满，所以写了 `andares` 时测量也按上限填满（结果里的 `pedido` 可以核对）。不写 `andares` 就沿用存档里这一趟的请求。
  `"reliquias": ["muralha","escudo",...]` 把遗物按顺序放进 5×4 的格子（账号里要有这么多件）。`"chefao": true` 才把「首领等级」类遗物计入请求（默认不计，它是加难度的）。
  `curaPorHorda`、宝箱、房间数这类遗物效果不走请求，这里没有核对。
- 每日词缀（例如「工程师伤害和生命 +20%」「瘟疫」）不在存档里，模拟不到。
- 1.1.3 里塔的升华经验比 1.1.0 高很多（同一存档同一段约 3.5 倍），对比时不要跨版本混用数字。

**刷图**：每个种子模拟 10 分钟，过图间隔按 4 秒算，药水计入（洞察药水是和经验加成相加，实际约 +8%，不是 +25%）。
默认套「推图」预设：存档如果是在巨像进行中存的，场上是「巨像」预设，不切换的话经验会低约 2%、金币低 3%～4%。
这 10 分钟里升级的英雄，跨过的等级所需经验会加回来；满级后经验进升华（`xpDoGrau`），也算在里面。队伍打不动这一关时经验记 0 并标成倒地。
有人倒地时引擎会像游戏里一样往回退关：这时数字是退到的那一关的，输出里会写明退到了哪一关。
对照两段真实存档区间：模拟比实际低 4%～19%，差的部分主要是巨像宝箱给的经验。

**巨像**：每种类型打一场，10 种合计。默认强度 2200、时长 1800 秒、同行 5 队、自动切到名为「巨像」的预设。
用 4 场存档里记录的真实战斗（104、107、108、112 号存档）校准：

| 同行玩家设定 | 模拟 / 实际 |
|---|---|
| 5 队弱玩家（`real`，取自一场真实战斗） | 0.62～0.97，平均 0.77 |
| 4 队弱玩家 + 1 队带 79 级女巫的真实队伍（`cal`，默认） | 0.73～1.09，平均 0.90 |
| 4 队弱玩家 + 1 个 94 级传说 60 女巫（`cal_wz60`） | 1.05～1.47，平均 1.2 |
| 5 队满级女巫队（`strong`） | 4～7 倍 |

倒地次数四场都和实际一致（13/12、25/26、22/22、14/14）。

- 伤害只统计自己队伍的输出，但同行玩家的减益会放大它，所以绝对值强烈依赖同场的人是谁。
- **绝对值只能当下限看。** 上表之后又对照了两场（都用 `cal`）：115 号存档 95 亿对实际 135.6 亿（0.70），118 号存档 145～153 亿对实际 234.2 亿（0.62～0.65）；
  118 那场换成它自己开打时的 5 队真实同行，是 131 亿（0.56），从开打 18.6 秒的真实状态接着模拟也只到 142 亿。
  版本没有变（存档里的符文引擎都认识），倒地次数仍然一致（4/4、5/5）。最可能的原因是真实战斗中同行队伍会中途换人，模拟里从头到尾是同一批。
  119 号存档那场（同样的装备，强度 2521，413 秒）实际只有 123.3 亿，模拟 111～120 亿（0.90～0.97）：装备没变，实际每秒伤害却比 118 那场低 28%，说明差的就是同行队伍。
  120 号存档那场是打满的（强度 1709，2871 秒）：实际 1272.7 亿，模拟 1048～1061 亿（0.82～0.83），倒地 21/21。
  122 号存档那场（强度 4537，6025 秒，第 2 种巨像，刺客站 1 号位）：实际 2066.3 亿，模拟 1745 亿（0.84），倒地 43 / 42。
  125 号存档记录的那场（强度 4515，4257 秒，第 2 种巨像）：实际 1762.6 亿，模拟 1270～1329 亿（0.72～0.75），倒地 28 / 28～29。
  127 号存档记录的那场（强度 4181，4093 秒，第 2 种巨像）：实际 1759.8 亿，倒地 25。中途换过装备，按开打前的装备模拟是 1449 亿（0.82），按打完时的装备是 1738 亿（0.99），倒地 26 / 25。
  133、137 号存档那场（新阵容刺客、女巫、工程师、治疗师的第一场，强度 5126，第 2 种巨像，还没打完）：前 235 秒实际 167.2 亿，按刺客实际带的推图配法模拟 166～182 亿（0.99～1.09）；第 355～1067 秒实际每秒 0.77 亿，模拟 0.81 亿（1.05）。巨像默认按「巨像」预设模拟，而这几段实际是用推图配法打的，核对时要用 `"preset": null`。
  143 号存档那场（新阵容，强度 3362，第 3 种巨像，刺客巨像配法、女巫出战压倒性诅咒 / 脆弱 / 诅咒，战斗记录确认；进行中）：到 1183.6 秒实际 2030.5 亿、倒地 8 次；模拟 1947 亿 ±55、倒地 8 次（0.96）；不带同行队伍模拟是 1614 亿（0.79）。
  150 号存档记录的那场（新阵容四人，强度 2927，第 3 种巨像，2374.6 秒）：实际 3877.2 亿、倒地 16 次；按换手套之前的装备（149 号存档）、刺客巨像预设模拟是 3931 亿 ±51、倒地 16 次（1.01）。如果刺客用的是刷箱子的预设，模拟只有 1244 亿，所以这场确实切回了巨像预设。
- 刷图对照：121 → 122 之间挂了 16.4 小时的 10-9，实际每人每小时 1.092 亿经验、537 万金币；模拟 1.048 亿、542 万，经验低 4%。
- 刷图对照：118 → 119 之间挂了 10.5 小时的 10-9，实际每人每小时 1.07 亿经验、592 万金币；模拟 1.023 亿、539 万，低 4% 和 9%。
- 相对涨幅仍然对得上：115 → 118 两场之间（刺客武器 +3 唤醒、全队升 97 级），实际每秒伤害 +51%，模拟预测 +47%。
- 装备、强化这类改动的相对涨幅在 `cal` 和 `real` 两种设定下基本一致，可信。
- 「自己带女巫」的收益依赖同场有没有别的女巫，要两种设定都看。

**误差**：单场巨像的随机波动约 ±8%，10 种合计后约 ±2.5%，默认 3 个样本后约 ±1%。

巨像样本：不写 `samples` 就是 3 个。写了 `cacada`（指定某一场）时每个样本都是同一场，所以只算 1 个；场次编号 24 个一轮，样本数上限 24。
涨幅只在基准有同样本号的结果时才给；基准那一边没有可比的样本时显示「基准没有可比的样本」，结果文件里 `delta` 是 `null`。

## 速度

同样的 57 个方案（每个 4 个刷图种子 + 10 场巨像）：旧脚本 178 秒，qsim 71 秒；重复运行走缓存，0.3 秒。
缓存文件 `cache.jsonl` 超过 64 MB 时，启动会自动只保留当前存档和引擎的条目。

## 和旧脚本相比修掉的问题

- 巨像预设不再用过期的手抄文件，直接读存档里的「巨像」预设。
- 巨像强度、时长、同行玩家改成按真实记录校准的默认值。
- 生成装备不再手算修正系数，词条、孔数（永恒多 1 孔）、附魔数值（随品质变化）都调引擎函数。
- 刷图计入药水。
- 每个结果带误差，不再凭单次结果下结论。
- 引擎函数尽量走具名导出，只剩 `est2` 一个内部函数依赖注入，由 `build_engine.py` 按代码结构自动找。
- `stats` 只算英雄自己的面板，不含宠物、符文这类全队加成；看宠物的效果用 `col` 或 `tower`。
